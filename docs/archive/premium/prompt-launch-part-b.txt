==================== PART B: Skinly Plus (branch feat/plus from the updated main; tag v0.3.0-rc1; version 0.3.0) ====================
OWNER DECISIONS (write them into docs/PLUS_SPEC.md and SPEC)
- Free: Calm light, Midnight, High contrast, Auto, five pets, scenes of the free themes, readability repair, own AI key, per-site memory. Plus: Ocean, Warm paper, Field with their scenes, and custom assets. All lists live in one config.
- Accounts are optional. Free works with no account and no network. Plus needs sign-in by email code (OTP), no passwords.
- Price comes from the server plans table, never hardcoded. Billing goes through a provider adapter; ship only a clearly marked test-mode provider, refused unless BILLING_MODE=test. The owner plugs in the real provider later.
- No cloud sync, no hosted AI, no telemetry. The backend never receives page data, URLs, origins, site lists or keys.
- Gating in the extension is a convenience, not security (open code); say so honestly in docs. Real enforcement is the signed entitlement from the server.

B1. Spec and rules: docs/PLUS_SPEC.md (plans, flows, data held: email, plan status, billing references; nothing else), docs/SECURITY_BACKEND.md (threat model: forged webhook, replay, token theft, RLS bypass, entitlement spoofing, abuse, account deletion), update CLAUDE.md, SPEC and AUDIT: fetch only under src/providers and src/backend; storage keys `auth` and `entitlement` added to the scanner list; tokens never reach content scripts, pages, logs or errors. Scanner rules for service_role, sk_live, rzp_, whsec_ and private keys in src, tests, dist and backend.
B2. Backend in backend/ (Supabase: Postgres, Auth, Edge Functions in TypeScript). Migrations: profiles, plans (id, name, interval, price_minor, currency, provider_ref, active), entitlements (user_id, plan, status, current_period_end, provider, provider_customer_ref, provider_subscription_ref, updated_at), billing_events (provider_event_id unique, type, received_at; no raw payload). RLS on every table; a user reads only their own entitlement and the active plans; all writes only by service role inside functions. SQL tests proving RLS (document `supabase test db`).
B3. Functions: get-entitlement (verifies the user JWT, returns a short-lived Ed25519-signed token: plan, sub, iat, kid, 3-day expiry), create-checkout (via adapter), billing-webhook (constant-time signature check, replay window, idempotent through billing_events, handles activated, renewed, cancelled, expired, refunded), delete-account (removes all rows and the auth user), test-checkout (test mode only). CORS from an ALLOWED_ORIGINS secret, strict input validation, per-user rate limit, generic errors, no PII in logs. All logic in pure TypeScript modules under backend/supabase/functions/_shared with no Deno-only APIs, so Vitest tests them: signature checks, forged and replayed webhooks, idempotency, state transitions, token signing and tamper, rate limit, validation. Billing adapter interface (createCheckout, verifyWebhook, parseEvent) with the test provider as the only implementation. scripts/gen-entitlement-keys.mjs (Node crypto) writes the private key to a gitignored private/ file and prints only the public key. .env.example files hold names only.
B4. Extension client in src/backend/: config from build env (VITE_SUPABASE_URL, VITE_SUPABASE_ANON_KEY, VITE_ENTITLEMENT_PUBKEY); missing config means "Plus not available in this build" and everything else works. Auth through the REST endpoints for email OTP (send code, verify, refresh), session in `auth`, refresh before expiry, sign-out wipes it. Entitlement fetched on demand and daily, verified with WebCrypto against the embedded public key, cached in `entitlement` with 7-day offline grace; a tampered, expired or wrong-key token counts as Free. src/plan/entitlements.ts becomes real: one `canUse(feature)` used by the popup flow, the options page, the AI validator step (clamp a Plus-only theme to the nearest free one when not entitled; tell the AI only the entitled theme ids; bump PROMPT_VERSION) and the auto script (a stored Plus theme on a lapsed account falls back to the nearest free theme; never a broken page; never delete local assets, just hide them). The auto script reads only a derived plan flag, never tokens.
