# Real-browser bugs (Edge testing, fix/real-browser-1)

Principle: a theme may recolour a site, never hide or damage its text, images or layout.
Status: every row is covered by a unit test (there is no browser here). Rows marked UNVERIFIED also need the human check in docs/HUMAN_CHECKS.md.

| # | Symptom | Cause | Fix | Test |
|---|---|---|---|---|
| A1 | Buttons, sidebar items and cards became solid accent blocks with invisible text | Text colours were set on `span`, `div` and other wrappers, so a label inside an accent button got the page text colour; every rule was forced with `!important` and a raised specificity, so a site's own class could never win | Typography rules skip anything inside a button or link (`:not(:where(button *, a *, ...))`); everything except the page root and the legacy colour attributes uses `:where` with no `!important`; every background colour is paired with a text colour | tests/plan/compile.test.ts "page-safety rules (every strategy)" and "forces only the page itself..." |
| A2 | Paragraph text invisible | Backgrounds painted on wrappers with a text colour that did not fit the site's own boxes | Wrapper boxes are not painted unless `protectBackgrounds` is false; strategy ladder (full, safe, text-only); the visual guard steps down and rolls back | tests/guard.test.ts "visual guard (pure)", "guard inside the applier" |
| A3 | Text typed in editors invisible | Text and background colours set on contenteditable ancestors without a pair; caret colour set on the page root | Caret colour only on fields (paired with their surface); the guard holds editable fields to 4.5 and checks the caret | tests/guard.test.ts "holds editable fields to 4.5 and checks the caret" |
| A4 | Text clipped | Base font size and line height rewritten on the root and body | No font-size, line-height, padding, margin, width, height, white-space or text-overflow changes, except the opt-in region layouts of the full strategy | tests/plan/compile.test.ts "contains no dangerous constructs" |
| A5 | Images behind content (z-index -1, CSS background-image, hero images) disappeared | Theme background painted on `body` and on wrapper boxes; the `[background]` attribute rule set `background-image: none` | Page background on `html` only (`body[bgcolor]` is made transparent); `background-color` only, never the shorthand; no `background-image` rule at all; nothing for media; the guard compares display, visibility, opacity, filter and background-image of the 30 largest media | tests/guard.test.ts "synthetic real-world fixtures never get damaging CSS", "fails when media loses ..." |
| A6 | Same strategy for dark apps and plain pages | No notion of page tone | Summary `page` facts (tone, bgImages, largeMedia, hasHeroMedia); a dark page with a dark theme starts at safe | tests/analyzer/summary.test.ts "reports page facts...", tests/guard.test.ts "a dark page with a dark theme starts at safe" |
| A7 | "Skinly couldn't run on this page" shown after a successful apply | Not reproduced without a browser. Removed candidates: a refused repeat injection of applier.js or scene.js turned into an error; a late failure after the theme was already on the page was shown as a total failure | `ensureApplier` and `ensureScene` ignore a refused repeat when the tab already has the script; the popup clears pet and scene notes at the start of a run and shows a neutral line when a theme is on the page | tests/inject.test.ts; UNVERIFIED in a real browser |
| A8 | Restore after the popup was reopened | (works at page level) | Tested through the page global only: theme, pet and whole-page blur are removed and the document is byte-identical | tests/restore-all.test.ts |
| B1 | Scene art not visible | Gutter measuring counted off-screen skip links, tiny nodes, far-away blocks and slim fixed bars, and measured a full-width block by its box instead of its text; the popup did not say why nothing showed | Accurate measuring; the popup shows the exact state in one line (off, not loaded, showing, narrow, none) | tests/features/freespace.test.ts "on app-style pages", tests/asset-here.test.ts "reports narrow and missing side space"; UNVERIFIED on real pages |
| B2 | Field scene missing its props at low density | Tank, helicopter and rifle were spread over the actor list and cut by the density share | Signature props first in the list | tests/features/scenes-art.test.ts "Field scene shows its signature props" |
| B3 | Custom asset only in Settings | No per-page control | "Use my picture on this page" in the popup, saved with the site record | tests/asset-here.test.ts |
| B4 | Pet motion buried | Movement, direction and speed were inside a closed details block | Motion and Speed in the popup; vertical bounce in a gutter; screen-edge fallback when there is no gutter | tests/popup-pet.test.ts, tests/features/pet-motion.test.ts "vertical bounce inside a gutter" |
| B5 | Field card cut off in the popup; import box hard to use | Fixed three-column grid, long Auto label, single-line input | Wrapping grid, scrollable body, textarea with format hint and a clear error, copy confirmation | tests/popup-scene.test.ts "theme code: a bad code is refused ...", tests/popup.test.ts "Copy theme code confirms in one line" |
| C1 | Theme only on the clicked page | "Always on this site" sat behind Keep and Remember | One "Keep on this site" button after any successful apply; in-page navigation re-applies | tests/popup.test.ts "per site", tests/auto.test.ts "applier-auto on a single-page app" |
| D1 | A rate limit with a long retry-after looked like a generic failure | Only the kind was kept | The soonest retry-after is shown as "Rate limit, try again in N seconds"; no probing | tests/providers/registry.test.ts "long retry-after", tests/ai/pipeline.test.ts "transform: rate limits" |
