## Step 2 — the scanner (`scripts/rename-check.mjs`)
Zero dependencies (Node built-ins only), ESM, readable in one screen, with a five-line usage comment at the top.
- Walks the repo from the project root; always skips `node_modules`, `dist`, `.git`, `private`, binary files (by extension and by NUL-byte sniff), and files over 2 MB.
- Matches the old-name patterns case-insensitively: `skinly` in any form.
- Applies the allowlist from `scripts/rename-allowlist.json`: entries of `{ "path": "<glob or prefix>", "pattern": "<optional regex>", "reason": "<why>" }`. Seed it with: class K paths; class G storage keys (exact strings); the legacy theme-code compat lines (`skinly1:` import path and its test), each with a reason. Every entry needs a non-empty `reason`; the scanner fails if one is missing.
- Output (compact, no per-line flood): `leftovers: N in M files` then the top 15 files with counts and one sample line each; `--summary` prints counts per class from a built-in class table (the same classes as the map); `--class A|B|...` lists only that class; `--json` prints machine-readable output; `--list-allowed` prints what the allowlist is currently hiding with counts.
- Exit code 0 if there are zero non-allowlisted hits, 1 otherwise, 2 on an internal error.
- Export the pure matching functions (`scan(fileEntries, allowlist)`, `classify(match)`) so the unit test can call them without touching the real repo.

## Step 3 — the test (`tests/rename-check.test.ts`)

No dependency on the real repo contents.
