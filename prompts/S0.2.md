## Steps

### A. Build `scripts/gate.mjs`
Requirements:
1. **Node built-ins only** (`node:child_process`, `node:fs`, `node:os`, `node:path`, `node:process`, `node:url`). Import `process` explicitly so eslint's `no-undef` cannot trip on it.
2. **No shell.** On Windows, Node 24 refuses to spawn `.cmd` files directly. Run each tool as `process.execPath <bin script>`, resolving the bin path from the package's own `package.json` `bin` field (typescript `tsc`, eslint `eslint`, vitest `vitest`). Run with `cwd` = repo root (derive from `import.meta.url`).
3. **Steps** (each timed):
   - `tsc`: `--noEmit --pretty false`; parse lines of the form `file(line,col): error TSnnnn: message`.
   - `eslint`: `. --quiet --format json`; parse the JSON from stdout, keep severity-2 messages as `file:line rule message`.
   - `vitest`: `run --reporter=json --outputFile=<temp file in os.tmpdir()>`; parse totals (files, tests, passed, failed) and, for each failed test, `file :: full test name :: first line of the failure message`. Delete the temp file afterwards. Never write the JSON into the repo.
4. **Flags:**
   - `--only tsc,eslint,vitest` (comma list; default all three).
   - `--tests <path> [<path>...]` — vitest file filters, passed through (everything after `--tests` up to the next `--` flag).
   - `--full` — print up to 200 lines per section instead of the default cap.
   - `--failures-file <path>` — write the failing test list (one per line, `file :: test name`) to that path, sorted.
5. **Output** (default cap: 40 lines total, truncate with `... N more (use --full)`):
   ```
   tsc     : 1 error   (3.1s)
     src/engine/dom.ts(57,25) TS2304 Cannot find name 'PropRecord'
   eslint  : 4 errors  (6.8s)
     src/ai/pipeline.ts:19 no-unused-vars ...
   vitest  : 1299 pass / 19 fail / 1318 tests in 88 files  (41.0s)
     tests/restore-markers.test.ts :: <name> :: <first message line>
   GATE: RED
   ```
   `GATE: GREEN` and exit code 0 only if every selected step has zero errors and zero failures; otherwise `GATE: RED` and exit code 1. If a tool crashes or its output cannot be parsed, print `GATE: ERROR (<step>)` with the first 20 lines of raw output and exit code 2.
6. Overall timeout 10 minutes; kill and report `ERROR` if exceeded.
7. Add one comment block at the top of the file explaining usage in five lines or fewer.
8. After creating it, run `npx eslint scripts/gate.mjs` and `npx tsc --noEmit --pretty false`. The gate script must add **no** eslint error and **no** new tsc error. Fix the script, not the config.

### B. Wire it
Add the single `gate` script line to `package.json`. Verify with `npm run gate -- --only vitest --tests tests/engine`: it must print `GATE: GREEN` (the engine tests pass at baseline). Verify `npm run gate` prints `GATE: RED` and exits non-zero at baseline.

### C. Measure the baseline (this is the important part)
Run each of these separately and record exact results and durations. Do not fix anything you find.
1. `npm run gate -- --failures-file workflow/BASELINE_FAILURES.txt` (full vitest run, which includes `tests/build.test.ts`, `tests/budgets.test.ts`, `tests/release.test.ts` that the recon skipped).
2. `npm run build` (writes `dist/`).
3. `npm run validate-dist`
4. `npm run contrast`
5. Count of `data-skinly-engine` in `dist/applier.js`, `dist/applier-auto.js`, `dist/scene.js`, `dist/palette.js`, `dist/background.js` (use the Grep tool with count output).
6. `git status --porcelain` and `git diff --ignore-cr-at-eol --stat` after all of the above.

### D. Record
Overwrite the "Gate baseline — filled by S0.2" section of `workflow/BASELINE.md` with:
- A table: step | result | duration (tsc, eslint, vitest, build, validate-dist, contrast).
- vitest: files, tests, pass, fail, plus the 5 (or however many) failing files with count per file.
- Results for the three previously unrun test files (pass/fail each, and whether they modified any tracked file).
- The marker counts from C5.
- A "Difference from recon" list: anything that does not match the recon figures (tsc 1, eslint 4, vitest 19 failing in 5 files, applier.js 1 marker hit, applier-auto.js 0). Do not explain away differences; record them plainly.
- "Expected red until fixed": which stages are supposed to clear which failures, mapped from `STAGES.md` (S1.1 tsc, S1.2 eslint, S2.x restore-markers, S3.x legacy tests). If a failing test does not fit any stage, say so under "Unmapped failures".
`workflow/BASELINE_FAILURES.txt` is the exact sorted failing-test list. Later sessions diff against it.

If any test or build modified a tracked file (step C6 shows unexpected changes), list the files in HANDOFF under "Bugs found" and do not revert them yourself.
