# S0.1 — Bootstrap workspace

## Session settings
- **Model:** Sonnet 5.5
- **Effort:** medium
- **Why:** structured file creation plus careful reading of legacy rules; no engine reasoning needed.

## CLI prompt (paste into a fresh Claude Code session started in `extension-new/`)
```
Read CLAUDE.md, then execute prompts/S0.1.md exactly. This is substage S0.1 only. Do not edit any existing source, config, test or doc file. Do not run any git write command. When finished, follow the Session close steps in CLAUDE.md and stop.
```

## Preconditions
- Working directory is `extension-new/`. `CLAUDE.md`, `specs.md`, `STAGES.md`, `CLAUDE.legacy.md` (the old CLAUDE.md, renamed by the owner) and `prompts/S0.1.md` exist.
- `git ls-files src/engine tests/engine` lists the engine files (they are committed). If they are untracked, stop and write BLOCKED: the owner must commit them first.
- No previous substage.

## Allowed scope
Create new files only, under: `workflow/`, `prompts/README.md`, `docs/MANUAL_CHECKLIST.md`, `docs/archive/.gitkeep`. Do **not** modify any existing file. Do not touch `package.json`, `src/`, `tests/`, `scripts/`, `docs/PROGRESS.md`, `autopilot-all.ps1`, `.env*`, or `private/`.

## Steps
1. **Sanity-check the recon facts** (read-only) and record the results in `workflow/BASELINE.md` under "Pre-flight": current branch and HEAD, `git status --porcelain` count, engine files tracked yes/no, `package.json` script names, `node_modules` present yes/no, node/npm versions. Do not run tsc, eslint, vitest or build (S0.2 does that).
2. **Reconcile legacy rules.** Read `CLAUDE.legacy.md` fully. Write `workflow/RULES.md`: a table with one row per legacy rule or hard constraint — number, one-line summary, and status `KEEP`, `CHANGE`, or `DROP`, with the reason. Apply these known overrides: rules mentioning Plus/premium/entitlements become `DROP` (removed in Stage 4); the "inline styles forbidden" rule is already relaxed for the engine (`CHANGE`); the "NO e2e" rule becomes `CHANGE` per decision D11 (zero-dependency harness allowed as a dev tool, outside `npm run check`). Where a legacy rule conflicts with `CLAUDE.md` or `specs.md`, the new files win; note the conflict. Keep any rule you are unsure about as `KEEP` and flag it.
3. **Create `workflow/PLAN.md`:** a status tracker generated from `STAGES.md`. One table with columns `ID | Title | Model/effort | Status | Date`. All 31 rows `TODO`, except S0.1 which you mark `DONE` at session close. Mark S7.1 and S7.2 as `TODO (optional, D11)`.
4. **Create `workflow/DECISIONS.md`:** copy decisions D1–D11 from `specs.md` §3 verbatim as a table, plus a section "Log" (empty) for later sessions to append to.
5. **Create `workflow/HANDOFF.md`** (written at close, per CLAUDE.md §5) and **`workflow/LOG.md`** (header line `date | ID | status | files touched | gate summary`).
6. **Create `workflow/BASELINE.md`** containing the Pre-flight section from step 1 and a placeholder "Gate baseline — filled by S0.2" section with the recon figures copied from `specs.md` §2 labelled "recon (unverified)".
7. **Create `prompts/README.md`:** three lines — each stage prompt is saved as `prompts/S<x.y>.md`; one substage per session; never commit from Claude Code.
8. **Create `docs/MANUAL_CHECKLIST.md`:** a skeleton with these headings and an empty checkbox list under each: Google, GitHub, Wikipedia, YouTube, natively dark site, shadow-DOM site, hover states, all 6 themes (one checkbox per theme: calm-light, midnight, ocean, warm-paper, high-contrast, field), Restore, per-site memory, pets, blur. For each, add the first two checks that apply (for example "theme click applies immediately", "Restore returns the page exactly"). Mark the file "finalised in S7.3".
9. **Create `docs/archive/.gitkeep`** (empty).
10. **Legacy artefact note:** in `workflow/RULES.md`, add a short section listing `PROMPTS.md`, `prompt-launch.txt`, `autopilot-all.ps1`, `docs/PROGRESS.md` as legacy agent artefacts that must not be executed or followed; they are archived in S4.5.

## Expected gate state
No gate. Nothing in `src/`, `tests/`, `scripts/`, or config changes. Verify at the end with `git diff --ignore-cr-at-eol --stat` (must be empty) and `git status --porcelain` (only new untracked files under the allowed paths plus the owner's own files).
