## Required behaviour

**Ledger model (I2).** Each element has one record. Replace the whole-attribute snapshot with:
- `hadStyleAttr: boolean` — `el.hasAttribute("style")` at the moment the element is first recorded (before the engine's first write);
- `props: Record<string, PropRecord>` where `PropRecord = { o, p, m }`: `o` original inline value of that property (`""` if none), `p` its original priority (`""` or `"important"`), `m` the value the engine wrote.

Remove the `origStyle` snapshot from the restore path. Nothing may restore the whole `style` attribute from a snapshot any more.

**`put(el, prop, value)`.** On the first write of a property for an element: record `o`/`p` from the element's current inline declaration, write `value` with priority `important`, then set `m` to the value **read back from the element** (`el.style.getPropertyValue(prop)`), not the string you passed in. Reason: browsers and jsdom normalise values (for example hex to `rgb(...)`), and the guard must compare like with like. If an entry already exists, keep `o`/`p` and update `m` (this is today's behaviour; do not add re-basing here, S2.2 does that). Custom properties (`--*`) go through the same path.

**`reset(el)`.** For each property in the element's record only (I3):
- if the current inline value equals `m` **and** the current priority is `important` (the engine's own write is still in place): put back the original (`setProperty(prop, o, p)` when `o` is not empty, otherwise `removeProperty(prop)`);
- otherwise the page has changed that property: leave it exactly as it is.
Then drop the record and the `data-skinly-engine` marker. Finally, if `hadStyleAttr` is false and the element's inline style is now empty, remove the `style` attribute (I6); if `hadStyleAttr` is true, keep the attribute even if it is now empty. Never touch a property that is not in the record.

**`restore()`.** Keep its overall structure (timers, rAF, observer, listeners, transitions, sheet, root marker). It must use the new `reset()`. For an element that carries the marker but has no record (record lost), remove only the marker and leave its styles alone; note this case in HANDOFF (S2.3 handles fresh instances).

`refreshBatch` currently calls `reset(el)` before recomputing (around line 365). Leave that call as is; with the new `reset()` it must still behave correctly (restore the engine's props, then re-write). Do not restructure it; S2.2 does. Verify it with the existing engine tests.

**Out of scope, but investigate and report:** if `suppressTransition` (or anything else) writes inline styles **outside** the ledger, that violates I2. Do not fix it here; describe it in HANDOFF under "Bugs found" with `file:line` so S2.2 can include it.

## Tests to add (unit, jsdom; through the public engine API, no new exports)
Create each scenario with a themed element, `apply`, flush as the existing tests do, then `restore()` and assert:
1. **No style attribute originally:** after restore, `hasAttribute("style")` is false.
2. **Original inline styles preserved:** `style="color: red; width: 10px"` returns to exactly those two declarations with the same values and priorities (compare per-property value + priority and the property count, not the raw attribute string).
3. **Original `!important` preserved:** `style="color: red !important"` comes back as red with priority `important`.
4. **Empty attribute kept:** `style=""` originally present is still present after restore.
5. **Unrelated page change survives (I3):** while themed, the page sets `el.style.width = "50px"`; after restore the width is still 50px and the engine's props are reverted.
6. **Page overwrote an engine property (I4):** while themed, the page sets `el.style.color = "blue"`; after restore the colour is still blue (not the original, not the engine value).
7. **Page removed the attribute:** while themed, the page calls `removeAttribute("style")`; restore does not resurrect the original declarations.
8. **Attribute kept when the page added its own style:** element had no attribute, the page adds `width` while themed; after restore the attribute remains and holds only the page's `width`.
9. **Custom property:** an inline `--x` value is restored exactly.
10. **Normalisation guard:** an element whose themed colour the engine wrote in a form the DOM normalises differently from the written string is still reverted on restore (this proves `m` is the read-back value).
11. **Idempotent:** calling `restore()` twice does not throw and changes nothing the second time.
12. **No leftovers:** after restore there is no `[data-skinly-engine]` element and no root `data-skinly` marker (add only if the existing tests do not already assert this).
Name tests so the invariant is visible (for example `I4: page-changed property is not overwritten on restore`).
