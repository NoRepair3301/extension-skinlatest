## Required behaviour
1. **Button state.** Restore is enabled only when there is something to restore on this tab (engine marker present in the main frame or any same-origin frame, or the site is themed/remembered per the design) and disabled with a clear state otherwise; while restoring it shows a busy state and ignores repeat clicks; after success it shows a short confirmation, then returns to the disabled state because nothing is left to restore. On ineligible pages it is disabled with the design's message. Keyboard and ARIA: focus is not lost, state is announced (`aria-disabled`, `aria-live` text), consistent with how the radios were handled in S5.2.
2. **State after Restore.** The page is back to its original; the site is paused so the auto path does not re-theme it on the next load (design section 6); the theme radios show no theme as active for this tab (the global default may stay stored; follow the design); reopening the popup shows the same restored state; clicking any theme un-pauses and applies (already implemented in S5.2: verify with a test, do not re-implement).
3. **Shortcut parity.** The Restore command (Alt+Shift+R or whatever `commands.ts` defines) and the popup button run the same restore path: all frames, same pause/state changes, same fresh-instance cleanup (D4/S2.3), same result. If today they diverge (different code paths, one skips frames or the pause), unify them behind one function and test both entry points.
4. **Robustness.** Restore with no live instance (extension reloaded) cleans via the marker (S2.3); Restore twice is harmless; Restore when the applier is missing or injection fails shows the design's error message and never leaves a half-restored page; Restore never hides the page (I1).
5. **No regression** of anything S5.2 delivered (theme click applies, remember site, no stacking).

## Exact-restore integration test (`tests/restore-exact.test.ts`)
Using jsdom with the real applier/engine and realistic fixtures (reuse the legacy-portal and other existing fixtures; add a small page with inline styles in several forms: none, `style=""`, `!important`, custom properties, legacy attributes like `bgcolor`):
- For each of the 6 themes: record `document.documentElement.outerHTML`, apply, restore, assert strict equality (D12/I11).
- After a theme swap sequence (A then B then C) then restore: equal to the original.
- After page changes while themed (the page adds a class, sets a style property, removes the style attribute): restore keeps the page's changes and leaves no engine writes (I3 to I5): assert on the exact expected DOM.
- Restore through the shortcut entry point and through the popup entry point produce identical DOM and identical stored state.
- Restore from a fresh instance (lost instance) yields the same exactness for the fixtures where S2.3's best-effort guarantees it; where it cannot, assert the documented best-effort result.
- Restore leaves no timers, observers, adopted sheets, markers or transition overrides (I7).
For each new test group show one deliberate breakage in a scratch copy (not committed) that makes it fail; list in HANDOFF which you verified.
