## Required behaviour

**A. Recognise the engine sheet.** `markerCleanup` must identify and remove the engine's adopted base stylesheet without false positives on page-owned sheets. Use an explicit, robust signature chosen by the engine (for example a sentinel first rule or a dedicated marker rule that the engine adds and the cleanup checks), exported from the engine module as a constant, not a guess on the first selector. Old-style sheets that `isOurSheet` already recognises must still be removed.

**B. Marker carries minimal ledger data.** The engine already marks every touched element with `data-skinly-engine`. Extend what that marker (or the root marker) holds so a fresh instance can undo the engine's work **without** the lost in-memory ledger. Suggested design (you may deviate, but record it in DECISIONS):
- The set of properties the engine can write is fixed; the cleanup needs them from one shared constant.
- Per element, store only what cannot be derived: the original inline `{prop: [value, priority]}` for properties the page itself had set inline before the engine wrote them. Elements with no such originals carry an empty marker value. Keep the encoding compact, escaped correctly, and size-capped (if the data would exceed the cap, drop the originals for that element and note it in the root marker rather than writing a huge attribute).
- Marker writes happen under `quiet()` so they never trigger the engine's own observer (I7). Do not rewrite the attribute on every `put()` in a hot loop: write it once per element when its record is first created and when originals change, and measure/justify the cost in HANDOFF.
- The live-instance `restore()` removes the marker like today; D12/I11 (text restore only in final `restore()`) still holds.

**C. Fresh-instance cleanup.** For each element carrying the marker: for every engine-written property, if the current inline priority is `important` (the engine's write is in place), put back the recorded original, or remove the property if none; if the property is not `important` or is absent, leave it (page wins, best effort per D4). Properties not in the engine's list are never touched (I3). If the element had no `style` attribute originally and its style is now empty, remove the attribute when that is knowable (store a one-bit "had no style attribute" flag in the marker); otherwise leave an empty attribute and say so in HANDOFF. Remove the element marker, the root markers, the engine sheet, and any engine-created transition override. Idempotent: running it twice, or running it when nothing was applied, changes nothing and does not throw. Works for open shadow roots and same-origin iframe documents like the live restore does.

**D. Do not break live restore.** The live `restore()` path and its exactness (I4-I6, D12) behave exactly as before. A fresh instance that applies a new theme after cleaning an old one must not stack or leak.
